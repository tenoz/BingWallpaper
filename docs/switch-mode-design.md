# 壁纸切换模式（自动间隔 + 切换模式）

## 需求

老大 2026-09-14 提出两组新设置：

1. **自动切换间隔**：手动 / 30 分钟 / 1 小时 / 4 小时 / 8 小时 / 12 小时 / 24 小时
2. **切换模式**：最新 / 循环 / 随机

外加一条 GUI 要求：加入新功能后，菜单按功能用分割线 + 小标题重新分类。

## 核心结论：下载节拍 ≠ 切换节拍

改造前 `refresh()` 把「拉新图」和「换壁纸」绑死，且 `applyAuto()` 硬编码永远取 `newestImage()`。

改造后拆成两条彼此独立的节拍：

| | 节拍 1 · 拉新图入库 | 节拍 2 · 换桌面壁纸 |
|---|---|---|
| 触发 | 每天 1 次（`dailyTime` 定点，轮询判定） | 每 60 秒轮询判定，距上次切换 ≥ 设定间隔 |
| 动作 | 抓接口、按清单去重、下载入库 | 从**本地图库**选一张，设为桌面 |
| 联网 | 需要 | **不需要** |

**为什么必须拆**：循环/随机模式下根本不需要联网；30 分钟就联网拉一次 Bing 是白费请求，且在 App Nap 下网络行为更容易出岔子。

## 一个必须知道的期望管理点

**「最新」模式 + 短间隔是矛盾的**。Bing 一天只出一张新图，所以「30 分钟 + 最新」的实际效果是**一天只变一次**——剩下 47 次判定里，目标图始终是同一张，画面纹丝不动。

短间隔（30 分钟 / 1 小时）只有配**循环**或**随机**才有意义。实现上「目标 == 当前」时会跳过设置调用，但计时照常推进。

## 老大拍板的决策（2026-09-14）

| # | 决策点 | 结果 |
|---|---|---|
| 1 | 默认状态 | **手动 + 最新**（升级后行为与旧版一致，不突然换壁纸） |
| 2 | 手动切图后的计时 | **归零重算**；菜单内**显示下次切换时刻** |
| 3 | 循环方向 | **从旧到新回卷**（与手动翻页按钮方向一致，避免迷惑） |
| 4 | 随机防重复 | **纯随机**，只排除「当前正显示的那张」 |

> 决策 3、4 首次征询时老大选了「从新到旧」和「洗牌袋」，复核后果后改回本表。
> 洗牌袋被否的原因：一轮 = 全库 2038 张，按 30 分钟一次要走 **42 天**，
> 「一轮内不重复」的实际体验与预期不符，而成本是多约 30 行 + 一份队列持久化。

## 数据模型

| Key | 取值 | 默认 |
|---|---|---|
| `switchMode` | `newest` / `cycle` / `random` | `newest` |
| `switchInterval` | `0`(手动) / `1800` / `3600` / `14400` / `28800` / `43200` / `86400` | `0` |
| `lastSwitch` | 计时基准时间戳（手动切图 / 改设置时刷新） | 空 |

`switchInterval` **用秒数存**，判定逻辑即 `now - lastSwitch >= switchInterval` 一句话，加新档位只改一处。

`nextSwitchAt`（`@Published`，非持久化）由 `lastSwitch + interval` 算出，供菜单显示倒计时。

## 行为规则

| 场景 | 行为 |
|---|---|
| 到点，目标 == 当前壁纸 | 跳过 `setWallpaper`，**计时照常推进**（否则会每分钟重试） |
| 循环模式 + 当前壁纸不在库内 | 从**最旧**那张开始 |
| 循环推到最新一张 | 回卷到最旧 |
| 随机抽到当前那张 | 排除当前后重抽 |
| 改模式 / 改间隔 | 重置计时基准，**不立即切**（避免设置时画面跳变） |
| 睡眠跨过多个间隔 | 唤醒后**只补切一次**，不补 N 次 |
| 手动切图 / 翻页 | 计时归零重算，倒计时刷新 |
| 填充方式变更（重应用当前图） | **不**重置计时（图没变） |
| 点「立即检查更新」 | 只拉新图入库，**不**换壁纸 |
| 每天定点检查后 | 走 `applyByMode()` 取一张（手动模式下即旧行为：换最新） |
| 下载目录变更 | 不影响计时（无洗牌袋，无需清空） |

## 关键技术决定

**长间隔挂在现有 60 秒轮询上，禁止新起 Timer。**
2026-09-04 ~ 09-08 连续三天「定时没触发」的根因就是一次性 Timer 错过瞬间即永久错过，连 App Nap 豁免都兜不住。8/12/24 小时这种长间隔用一次性 Timer 等于重蹈覆辙。复用现有轮询后：零新增定时器，进程活过任意一分钟即补跑，天然自愈。

代价（已接受）：**合盖睡眠期间不切换**，唤醒后若已超间隔则补切一次。

**循环模式不存游标。**
复用现有 `step()` 的「从系统当前壁纸反查索引」思路——App 重启、用户在系统设置里换图、库目录增删文件都不会错乱。但两者语义不同，故抽出带 `wrap` 开关的 `adjacent(_:wrap:)`：
- 手动翻页 → `wrap: false`（到边界夹紧，保持原行为）
- 自动循环 → `wrap: true`（到边界回卷）

**倒计时用绝对时刻。**
新增 `@Published var nextSwitchAt: Date?`，在 60 秒 tick 里更新。显示绝对时刻（如「下次切换 12:34」）而非「还有 12 分钟」——菜单久开时相对时间会显示过期数据，绝对时刻不会。副作用是 60 秒 tick 的更新会触发 SwiftUI 重绘，菜单打开时倒计时自动刷新，无需额外机制。

## 菜单新结构

```
[当前壁纸预览图 + 左右翻页按钮]
文件名 / 状态 / 目录
────────────────────────────
切换壁纸
  切换模式：最新            ▸
  自动切换：手动            ▸
  下次切换 12:34                ← 仅自动模式时显示
  设为最新
  随机一张
────────────────────────────
显示
  壁纸填充：充满屏幕        ▸
────────────────────────────
下载与更新
  更新时间：每天 09:30      ▸
  立即检查更新
  打开壁纸文件夹
  选择下载目录…
────────────────────────────
通用
  [开机启动]
  关于 Bing Wallpaper
  退出
```

「切换模式」「自动切换」两行沿用 `SubmenuRow` + `NSMenu.popUp` 右侧弹出（**勿改回 SwiftUI `Menu`**，它只能向下弹）。菜单宽度维持 280px。
