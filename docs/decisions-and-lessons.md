## 二、工程方法教训（踩出来的，跨项目通用）

这几条都不是"这个项目的特性"，而是**做事方法**上的坑，换项目同样适用。

1. **空跑（dry-run）的计数对不上就必须追到底**，不能只看"能跑通"。
   回填的去重 bug（`OHR.OHR.XXX` 双前缀，会让 2000 张全部重下）就是靠
   dry-run 显示"已有 0"才暴露的——正常应该有 15 张才对。

2. **判定文件有效性别用 `head -c 3 | od -An -tx1 | grep` 这种脆弱管道。**
   曾误报 28 张 JPEG "损坏"，实际文件完好（sips 能读出分辨率），
   是 shell 管道匹配的问题。**改用 Python 直接读字节判定。**

3. **核验路径存在性要逐个 `ls`，别信 `grep -oE` 正则提取的结果。**
   正则提取路径会让死引用审计产生大量假阳性，得出"合规"的错误结论。

4. **批量拉远端索引必须带重试**，否则会静默丢掉整月数据。
   68 个月索引首次全量挂了 3 个月，加 3 次重试后 2040 条全部拿到。

5. **`build.sh 2>&1 | tail` 会吞掉退出码**（管道返回的是 `tail` 的退出码）。
   验收脚本要看 `EXIT=$?`，否则构建失败也会显示"成功"。

6. **改完必须验证，且不靠间接证据。**（本项目铁律）
   例：别用"壁纸是最新的"推断定时器工作过——App 启动时本来就会抓一次；
   要看**落盘时间**是不是落在构建/启动时刻之外。

7. **GUI 改动别指望在 agent shell 里截图自证。**
   跑 `NSApp.runModal` 的探针进程会被环境 SIGTERM（exit 137）；
   即便截到图，也要先确认图里真有目标窗口——曾把拍到 Figma 桌面的截图
   当成"弹窗验证通过"，给出错误结论。模态弹窗样式一律交老大目验。

8. **BSD `grep` 的 `\|` 不是"或"**——要 `grep -E` 或分开查。
   曾因此出现"0 处匹配"的假阴性，差点误判代码已清理干净。
